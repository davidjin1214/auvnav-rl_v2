## 1. 本轮新增的实测：③ 可以零成本精确量化

### 1.1 方法

所有 `test/seed_*.json` 里都存着 `eval_episode_results` —— 逐回合记录，每条带它的 manifest `seed`。选点用的验证集是 `manifest_seed = 1250` 起的 **40** 条，终报测试集是同一起点的 **100** 条。于是可以把每个已刊单元的 100 回合直接劈开：

- **`sel40`** = 种子 1250–1289：**参与过**检查点选择与 $\alpha_{\mathrm{BC}}$ 后验选择的那 40 条；
- **`hold60`** = 种子 1290–1349：**任何选点规则都没见过**的 60 条。

`hold60` 是不重跑任何东西就能拿到的、最接近"真正留出集"的读数。复现：

```bash
python paper/thesis_ch5/tools/ch5_holdout_split_audit.py
```

顺带**四项独立核实**（都不是从文档抄的）：

- 主线 formal 单元的 `validation/seed_42/*.json` 实测为 **40 条、种子 1250–1289、`episode_id = single_u10_cross_tgt15_ep_0000…`** → ③ 的"前缀子集"成立，与终报 100 条的前 40 条**逐条同一实例**；
- **筛查单元的 `test/seed_*.json` 也是 40 条、种子 1250–1289** → $(\beta_1,\beta_2)$ 筛查的"测试集"与它自己的验证集**完全相同**，且是终报测试集的子集（见 §3.2）；
- 全部已刊数字（0.592/0.672/0.596、0.524/0.588/0.534、0.902/0.918/0.928/0.922/0.934、0.878/0.740/0.910、备选 0.894、筛查 0.883±0.031 与 0.917±0.012 等）**逐格从本机逐回合记录复算吻合**；
- 本机 `results/offline/**` 下 **无任何 `.pt`**（检查点只在 Drive）。

### 1.3 一个必须一并说明的限制

`sel40` 与 `hold60` 之间还有**内在难度差**，不能把二者之差直接读成"选点红利"。铁证：**采集器**这条基线**从未做过任何选点**，它在 crosscomp 上的 `sel40 − hold60` 仍是 $-8.3$ pp。所以：

- **`hold60` 不是"改正后的真值"**，它是"选点规则没碰过的一个子集上的读数"，样本更小（60 对 100）、难度分布也不同；
- 但**同一 `hold60` 子集上的组间比较是干净的**——难度差在两侧共模。上表里所有"差"都属这一类，**可以直接引用**；绝对水平（0.907、0.537 等）不可直接替换正文数字。

## 3. Q2：「守得住的」是否真守得住 → **大体成立，两处需修正**

### 3.1 确实守得住（本轮逐项核过）

- **§5.7.2 建立在 `worldcomp-1000` 上** ✓ —— 该数据集 `seed=0 / num_episodes=1000` → 训练种子 0–999，评估 1250–1349，**不相交**（本机 `metadata.json` 直证）。
- **§5.7.3 / §5.7.4 两项消融只在 1000 回合与 worldcomp 上执行** ✓ —— 逐种子表与本机结果目录一致（`stage_e_critic_penalty_off/..._ep1000`、`critic_ln_off/..._ep1000`、`worldcomp_critic_penalty_off_probe/..._ep1000`）。
- **§5.5 / §5.8 / §5.9 三节不沾 ③** ✓ —— 三节均明写不作验证集选点（`online.tex:371`、`boundary.tex:256`、`algo_compare.tex:295`）。
- **§5.8 亚临界锚点对照的是 1000 回合的 $0.902$**，非 2000 格 ✓（`boundary.tex:188`）。
- **§5.8 / §5.9 全部数据集在 ① 上干净** ✓ —— 本机实测 8 个相关数据集均为 `seed=0 / 1000 回合`，而全部 8 个 benchmark key 的最小 `manifest_seed` 为 **1100**，不可能相交。

### 3.2 $(\beta_1,\beta_2)$ 的「不塌」→ **结论成立，理由不完整，代价低估**

评估写：「筛查虽含污染块，但该配置在**干净的 1000 块上同样以均值与离散度胜出**（$0.883\pm0.031$ 居该块首位），选择结论不塌；仅『在两个数据集上同时胜出』一句须按新结果重述。」

**结论我同意，且本机复算证实 $0.883\pm0.031$ 确为 1000 块六格之首（均值最高、离散度最小、最弱种子 $0.850$ 亦为该块最高）。** 三点修正：

1. **理由只覆盖了 ①，没覆盖 ③。** 「干净的 1000 块」是相对 ① 而言干净；在 ③ 面上，**1000 块与 2000 块一样没有留出集**（§2 C1）。所以正确的说法是：*选择结论对 ① 不塌（有一个未受污染的数据块独立支持同一结论），对 ③ 则两块同病、但因六格同集比较、偏差共模，选择的相对序不受威胁*。
2. **"仅一句须重述"低估了。** 除 §5.7.m 那句，还有 tab:ch5_rebrac_screen caption 的三处跨块最优性断言与两个 2000 块数字（§2 B2），以及 §5.7.5「跨种子稳健性优选而非单点最高值」这一论述——它的凭据句正是那条 caption。
3. **若重采后 $(4.0,2.0)$ 在新 2000 块上不再胜出**，须改的不止措辞，而是**选择程序的叙事**：从"在两个数据集上同时胜出后升入正式协议"改成"在 1000 块上选定后跨数据集沿用"。这在论文里是可接受的（§5.7.m 本就有"$\beta_1$ 可跨数据集迁移"的理由句），但属于**论证结构改动**，不是一句话替换。
   —— **§5.9 沿用 $(4.0,2.0)$ 不受牵动，这一条守得住**：`algo_compare.tex:295` 写的是「沿主线筛查所锁定」，是**来源陈述**而非最优性断言。

### 3.3 §5.7.2 的「差距闭合过半」→ **不守**

§5.7.2 末段（`rebrac.tex:309`）把中心问题的肯定回答明确挂在三项**正向可观测量**上：明显高于同数据纯行为克隆、**差距闭合过半**、点估计不低于特权参照。前后两项在 `hold60` 上都稳（$+7.3$ pp；$0.907 > 0.887$），**中间一项掉到 $48.9\%$**（分母同用 `hold60` 上的采集器 $0.983$ 与纯 BC $0.833$）。

这不是塌方——序不变、幅度接近一半——但评估把 §5.7.2 整节列进"两条路均不动"是**过强**。「闭合过半」是 rev.4 重做时**专门挑出来承担肯定回答**的三个支点之一，它对 ③ 敏感这件事应当进裁决材料。

（同一算法下 §5.6.m 的 $48.5\%$ 在 `hold60` 上变成 $35.6\%$，一并登记。）

## 4. Q3：三条 ★ 推断的可靠度

### ★1 「污染只会**抬高** 2000 格」→ **不成立（作为断言）；应降级为"方向合乎直觉、未测、且未必单调"**

评估自己标了推断，但**下游把它当结论用了**：§2.3 的整张不对称风险表、§4 的「中心命题不在污染面上」、§5 的选项排序，全部建立在这条上。它需要比"离线 RL 在评估任务实例上训练一般有利"更硬的东西。三点：

1. **符号未必为正。** 采集器在 2000 回合上的采集成功率是 **0.8855**，即约 **11% 的训练轨迹本身是失败的**。落在评估实例上的那 100 条里，按同比例约 11 条的示范轨迹以越界/超时告终；行为约束方法（尤其 $\alpha_{\mathrm{BC}}$ 后验选到 $0.15$ 的 TD3+BC 与 $\beta_1{=}4.0$ 的 ReBRAC-Q）在这些实例上被**更强地拉向一条失败示范**。抬高与压低同时存在，净效应未知。
2. **本轮实测给出反向旁证（限于 ③，不能直接外推到 ①，但足以动摇"重合⇒抬高"这一直觉）**：ReBRAC-Q 三个 crosscomp 格在**参与过选点**的 40 条上的成绩**反而低于**没参与的 60 条（$-1.2$、$-4.7$、$-5.7$ pp）。"评估实例被算法见过 ⇒ 读数被抬高"在本数据上并不自动成立。
3. **正确的说法**：污染的方向与幅度**是可测的**，且测法很便宜（§5 的 ①-c）。在测出来之前，"只会抬高"不宜作为处置论证的前提。

### ★2 「共模偏差在组间差值中大部分抵消」→ **成立，且本轮获得直接实测支持；一处例外**

评估说"未量化"。现在量化了（对 ③ 而言）：把选点重合整段剔除后，**同数据格的组间差值无一反号，且全部变大**——$23.0\to28.0$、$32.2\to40.0$、$-7.6\to-9.0$、$-5.4\to-6.0$、$-16.2\to-17.3$。共模抵消不仅成立，而且现有报告是**偏保守**的那一侧。

评估补的那条"选点自由度不对称、红利偏向弱者（TD3+BC 每个规模额外后验选 $\alpha_{\mathrm{BC}}$）、故对 23.0/32.2 pp 是保守方向"——**成立，且被实测证实**（剔除后差距扩大正是这个方向）。

**例外**：闭合比例不是纯差值（带分母），共模不保 → §3.3。评估的"大部分抵消"应加一句"限于差值型量，比值型量另论"。

### ★3 「翻转可能被推翻」→ **成立，但偏悲观；应分两级门槛**

评估的依据是"$+1.6$ pp 裕度太薄 + 被抬高的正是这一侧"。补两点：

1. **章内真正的断言不是"2000 > 1000"，而是"**未再检出**回落"**（`rebrac.tex:270` 与 fig 的 caption 在 rev.4/收尾轮已逐字统一到这个强度）。因此存活门槛不是"点估计仍为正"，而是"不出现与 TD3+BC 同量级的可复现回落"。两级：
   - 污染幅度 $\delta \gtrsim 2$ pp → 「点估计反而略高」那半句失效；
   - $\delta \gtrsim 5\text{–}7$ pp → 才构成与 TD3+BC 的 $-7.6$ pp / 纯 BC 的 $-5.4$ pp 同量级的回落，论述才真正被推翻。
2. **`hold60` 上翻转变强**：$+3.0$ pp，5/5 种子不为负，配对 $t=2.09$（已刊 100 回合上是 $+1.6$ pp、$t=1.06$、有一个负种子）。这意味着推翻它所需的 $\delta$ 比 $+1.6$ pp 所暗示的**更大**。

综合：**"可能被推翻"仍应保留为真实风险**（$\delta$ 完全未测），但"翻转很可能保不住"这个隐含语气不该带进裁决——需要的是一次测量，不是一次预判。

## 5. Q4：处置选项 → **需修正，漏了第三条路**

### 5.1 漏掉的路径

**③-c ｜ 用现存逐回合记录重算，零算力、零重跑、正文数字一个不动。**
本轮已经跑完（§1）。它把 ③ 从"承认一个未量化的敞口"变成"披露一个**已量化**的敞口"：在 §5.3.6 与 §5.7.m 如实写清嵌套关系，再在 §5.7.m 的诚实限定段加一句敏感性读数（例如"剔除参与选点的 40 条后，两千回合对一千回合的差由 $+1.6$ 升至 $+3.0$ 个百分点、五个种子无一为负；可部署协议与特权参照的差由 $+0.6$ 升至 $+2.0$ 个百分点"）。
**成本**：③-b 的五处口径句 + 一句读数。**收益**：答辩敞口从"你没有独立测试集"变成"我知道、我量化过、结论方向不变（闭合比例除外）"。
**代价**：会引入新数字，须按 `prompt_playbook.md` 走重流程；且 §3.3 那条不利读数（48.9%）一并进正文——**这正是它诚实的地方，也是须用户拍板的地方**。

**①-c ｜ 在现有 2000 格检查点上补一次"干净 manifest"终检。**
生成一份与训练种子区间 0–1999 **和**现测试集 1250–1349 都不相交的 100 回合 manifest（如 `manifest_seed = 3000`），对已有五个种子的检查点**只跑评估、不重训、不重采**。这是**唯一能直接测出 ★1 那个 $\delta$ 的办法**，也是 ①-a 与 ①-b 之间真正的中间态：
- 若干净读数仍不低于 1000 回合的 $0.902$ → 翻转论述以"加一条敏感性读数 + 一句披露"保住，**不必重采重跑**；
- 若明显更低 → 拿到了硬证据再走 ①-b 降级，**且降级有依据而非因怀疑而降级**；
- 若介于两者 → 至少 ①-a 的重采有了明确的必要性论证。

**前置条件（须先确认）**：2000 格五个种子的 `.pt` 是否还在 Drive。**本机 `results/offline/**` 下 `.pt` 数为 0**，`selected_checkpoint.json` 里记着文件名（如 `agent_step_00066752.pt`）但文件本身未同步。若 Drive 侧已清，这条路作废，格局回到评估原来的四选项。

**注意**：①-c 与 ③-c 各管一半，**不能互相替代**——`hold60` 重算解决不了 ①（2000 格的全部 100 条都在训练集里，`hold60` 只是选点意义上干净）；新 manifest 补评解决不了旧数字的 ③ 敞口。两条一起做才完整，而两条加起来仍远低于 ①-a。

### 5.3 对起草者倾向（①-a + ③-b）的判断

**在补上第三条路之前，这个倾向是合理的；补上之后，它的排序应当改。**

理由：①-a 是四个选项里**唯一没有先测就直接付最大代价**的一个。评估自己承认"翻转能否保住"完全取决于一个未测的量（★1），却把处置定在"重采重跑"——那是在**赌**这个量小。而 ①-c 用一次纯评估就能把这个赌变成一次读数。

我的建议排序（**仅供参考，不构成决定**）：

1. **先做 ③-c**（已完成，零成本）+ **确认 Drive 侧 2000 格检查点是否还在**；
2. 若在 → **做 ①-c**，按结果分流：干净读数守住则走「①-b′ = 披露 + 敏感性读数、翻转论述保留但明写其证据基础」；守不住则走 ①-b（降级）或 ①-a（重采）；
3. 若检查点已清 → 回到评估原格局，此时 ①-a 的理由才真正成立；
4. ③ 一侧走 **③-c**（= ③-b + 一句已量化的敏感性读数），不走 ③-a。

**顺带（与裁决无关但应一并处理）**：跑一次 `python -m scripts.audit_seed_overlap` 覆盖 Drive 侧的含噪 2000 数据集，把 §2 A1 这个未知项关掉。
