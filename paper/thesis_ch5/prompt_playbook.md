# 第 5 章写作 Prompt Playbook（总纲）

> 定位：本文件是「**怎么写下一个写作/复审 prompt**」的元层总纲，与 5 份已归档的具体模板（见 §6 索引）及 `next_session_prompt.md`（当前进度的现成冷启动 prompt）配套使用。
> 来源：对 2026-05-30（写作启动）至 2026-06-19（§5.6 闭环）全部写作会话首条 prompt 的系统性回顾提炼（2026-07-02）。
> 用法：起草 §5.7+ 各节的新会话 prompt 时，先按 §2 选会话类型，再对照 §3 十要素逐条检查，关键句可从 §4 直接复制。

---

## 1. 核心经验一句话

**结构决策前置锁定 + 中心命题原话照用 + 复审与起草分会话**，是 §5.5/§5.6 一两轮定稿、而 §5.1/§5.2 六轮返工（含一次推倒重写）的最大差别。

## 2. 每个结果节的标准会话序列

每写一节，按顺序开独立会话（每个 prompt 冷启动自足：含项目路径、branch、conda env）：

| # | 会话类型 | 要点 | 参照模板 |
|---|---|---|---|
| 1 | **起草** | 本节角色 + 只写本节增量 + 起草后同会话内做一轮自足对抗复审 | 骨架见 §4.1（无归档模板） |
| 2 | **独立对抗复审**（新会话） | 冷启动、多子 agent 并行分维度、CRIT/HIGH/MED/LOW 分级、逐句引证 | `section_5_6_review_prompt.md` 换参 |
| 3 | **系统性复审**（按已定稿节标准） | 以 §5.5（发现链组织）为活标尺，指名上一轮复审的缺口维度 | `section_5_5_restructure_prompt.md` |
| 4 | **插图设计与绘制**（独立会话） | 先规划对齐再画；`_ch5_style.py` 复用 + 六条硬规范 | 骨架见 §4.3 |
| 5 | **commit 门控** | 明确要求才 commit；message 走 `docs(thesis): ...` | — |

复审轮数按节的分量伸缩：铺垫节（§5.8/§5.9）步骤 2+3 可合并为一轮；章重心（§5.7）应完整走完，且步骤 3 可以「按 §5.5+§5.6 双标尺」执行。

## 3. Prompt 十要素 checklist

每个写作/复审 prompt 发出前逐条对照：

1. **三重身份 + 质疑授权**：「AUV 运动规划 × RL 资深专家 + 严格中文博士论文外审人 + 母语级中文学术编辑」，并附「不必拘泥既有 spec——发现 spec 有问题就提出来」。质疑授权多次抓到 spec 自身的毛病并触发回写，不可省。
2. **「本次对话唯一任务」+ 本轮性质声明**：明确是起草 / 复审 / 润色 / 绘图，且明确**不是什么**（「本轮不是重写」「这是润色，不是推倒重写」），防止越权改结构。
3. **按序必读清单**：spec → 审查/写作对象 → 邻节锚（跨节一致性）→ ground-truth 数据文档 → 素材源。要求「先读完再动」。
4. **中心命题原话照用**：整段引入 spec §0.1 的锁定表述，注明「全章只论证这一句」；结果节 prompt 另加一句「本节为中心命题贡献哪一块」。
5. **已锁决策 vs 授权重开，显式分开**：「已锁不重开」列表（结构、标题、术语、§5.4 公式口径）与「本轮授权重开」范围分开写。若请求重写，必须列出用户的具体不满（06-07 推倒重写成功的关键）。
6. **红线子集内嵌**：只引与本节相关的 §0.4 机制归因红线 + §0.5.9 语体 + §0.5.10 术语条目，不整段搬运 spec。
7. **数字纪律**：ground truth 指针 + 「禁止凭记忆、禁止以成稿自述或其头部注释为准、实时回查」。§5.6 的离散度自相矛盾硬伤即由此抓出。
8. **流程门控**：先诊断 → 成文方案 → **硬停**（只卡文件改动，不卡 AskUserQuestion 对齐性提问）→ 用户确认 → 落地 → 编译验证 → 条对条自查。复审派多个独立子 agent 并行分维度（语体 / 数字忠实 / 论证逻辑 / 红线与跨节一致）。
9. **反 churn 护栏**：「若某段已合格，明说『保留不动』，不为改而改」「诚实分级，不为凑评级制造不存在的 CRITICAL」「只有 HIGH/CRITICAL 必改，MEDIUM 可选，LOW 仅记录」。
10. **工程交付纪律**：locked 文件用 Edit 不用 Write；`latexmk -pdf -xelatex` 0 undefined ref / 0 undefined citation / bibtex 0 warning；改 `refs.bib` 后手动 `rm -f main.bbl main.aux main.fdb_latexmk` 再从零编译（bbl stale 坑）；成功后 `latexmk -c`；新 cite 先联网核验著录；**不 commit 除非明确要求**。

## 4. 分类型骨架与可复制关键句

### 4.1 起草类（结果节，无归档模板，骨架如下）

```
身份三重设定 + 质疑授权
【第 5 章中心命题（原话照用）】
【§5.k 的角色】＝ 在中心命题中贡献哪一块；「不是独立 paper」；上承哪节、为哪节立问题设定
【先读清单】spec 专项块 → 邻节（口径/术语/零跨章/记号复用）→ ground truth（关键锚「回查核对、不照抄」）
【写什么】子节级骨架（发现链组织：每子节回答一个明确问题、图/表支撑、问题→证据→结论齐备）
       + §5.k.m 实施细节与可复现性（NO APPENDIX；只写本节增量，协议指针回 §5.3/§5.4）
【红线（严守）】本节相关子集
【流程】起草 → 同会话内 authoring/review 分离的一轮自足对抗复审 → 编译验证；不 commit
```

关键句：
- 「相对 §5.4 已定义的 X，只交代本节实验所需增量。」
- 「负面/退化结果作 finding（§0.5.6），不降级为 limitation。」

### 4.2 复审类（直接用归档模板换参）

换参位置：审查对象文件、ground-truth 指针、「已确认起点」举例、本节专属红线。保留不动的后期精化：

- 「这是 authoring/review 分离的复审：不要因为成稿『看起来完整』就放水，逐句核实、主动证伪，而非通读印象。」
- 「数字一律实时回查 ground-truth 源文档，禁止凭记忆，也禁止以成稿自述或其头部注释为准。」
- 「硬停只卡文件改动，不卡对齐性提问：可以用 AskUserQuestion 就关键结构决策与我对齐，但在我明确确认方案之前，绝不编辑任何文件。」
- 「诚实分级：不要为凑评级制造不存在的 CRITICAL。」
- **第二轮复审必须指名第一轮的缺口维度**（§5.5 第二轮的四缺口：展示太少 / 发现链被压没 / 缺学习曲线 / 语域），并声明「不要只重复上一轮的范围」。

### 4.3 插图类（独立会话，先规划对齐再画）

- 强制复用 `figures/scripts/_ch5_style.py`（Arial 7–8.5pt、低饱和墨色 `COLORS`、138mm 宽、`pdf.fonttype=42`）；可小幅扩展、不破坏既有约定。
- 六条硬规范：宽 ≤138mm / A4 可读 / 线可区分 / 不重叠 / 图内少字（英文极简）/ Nature 风格（细线、低饱和、无 chart-junk、矢量 PDF、横平竖直）。
- s0/s1/s2 配色与记号须与 Fig 5.1/5.2 跨节一致。
- **图红线随节型反转，prompt 里显式点明「切勿照搬」**：结果节图必须画结果数字（柱高/折线）；setup/method 节图内零结果数字。
- 数据取自 ground truth 文档精确数字，勿凭记忆；聚合呈现（均值 ± 离散度），不画 per-seed 散点（除非该节已有先例）。

### 4.4 润色类（语言层，结构已锁时用）

- 声明「结构与分工已锁，不重开：不合并、不拆节、不调节序；润色只在句子/段落语言层，不破坏论证骨架、不改 cite、不挪论点」。
- 若走 nature-polishing 等英文倾向 skill，须附「**产出保持中文**——不套用英文句法、不把中文改写成『英译中』腔；若 skill 倾向英文化，以『中文学术编辑』身份接管，只取其论证打磨能力」。
- 语病靶清单可直接沿用：直译腔 / 破折号插入语成瘾 / 强调引号成瘾 / 对举句式（清单换皮）/ 汇报语态 / 序数枚举。

## 5. 反模式（回顾中实际踩过的坑）

1. **同一 prompt 开多个顶层并行会话**：06-05 与 06-06 各有 4 份完全相同的会话副本，互无信息增量。多视角应在**一个会话内派多子 agent**实现。
2. **结构决策拖入语言迭代**：§5.1/§5.2 的「两节分工」问题拖到第五轮才正面解决，导致推倒重写。结构问题先用 AskUserQuestion 拍板锁定，再进语言层。
3. **复审第二轮不指名上一轮缺口** → 退化为重复劳动。
4. **凭记忆写数字 / 信成稿自述**：多次复审的 CRITICAL 硬伤（离散度矛盾、cite 张冠李戴、样本效率立论用错 k）全部源于此。
5. **图红线跨节照搬**（结果节 vs setup 节相反）。
6. **prompt 不自足**：依赖上一会话隐性上下文的 prompt 在 compact/新会话后失效；一切必读、锁定、红线都要落在 prompt 文字里。
