## C. §5.1 段落级蓝图（5 段，voice = dissertation 章；每段：主旨句 + beats + cite slot + 红线 guard）

> 注：主旨句用接近定稿的学术中文写出（供评判 voice），其余写 beats。最终定稿每段 3–4 句封顶（§0.5.7）。引言不携带实验数字。

### ¶1 — 问题与动机（抽象层）

- **主旨句（拟）**：「自主航行器要在真实环境中可靠导航，必须应对一个**自身无法完整观测的环境流场**：它持续地改变航行器的运动，而航行器在部署中通常只能在自身所在的一点感知这一流场。」
- beats：
  - 流场空间非均匀、随时间演化；动力学由作用于**整体载体**的流场驱动，而 onboard 传感只给出**局部、瞬时**的一瞥 → 本质是 partial observability，而非几何规划问题。
  - 为何是部署现实：外部观测系统 / simulator 提供的流场全貌在真实海洋作业中不可得；可依赖的只有载体自带的有限传感。
  - stakes：这把"导航"从几何问题变成"在不可完整观测的外部力场中决策"，是经典 model-based 控制与全局规划难以直接覆盖的一类问题。
- cite slot：① partial observability / POMDP 决策背景 1 篇综述；② 学习式 flow-aware 航行器导航的动机性工作 1–2 篇（代表作待 refs.bib 核实，**不臆造 key**）。
- 红线 guard：**不**点名涡街 / REMUS / DVL / 具体 Re；"环境流场""局部可观测"首次出现各给 1 句直觉定义（§0.5.1）。

### ¶2 — 核心科学问题 + 不对称权重

- **主旨句（拟）**：「本章问一个直接的问题：在这种**只有局部感知**的设定下，强化学习能把基于局部信息的导航推进到什么程度？」
- beats：
  - 拆两面：(a) 当航行器能与环境**持续交互**时（online）；(b) 当它**只能从既有日志数据离线学习**、且**部署时不允许获得任何特权信息**时（offline）。
  - **不对称权重（挑明）**：offline 是本章核心贡献；online 作为**诊断与铺垫**，先确立任务可学性与瓶颈所在，**以此框定** offline 结果的意义。用"我们先…以此框定本章的核心贡献…"句式。
  - 为何 offline 是更贴近部署的问法：部署受限场景常无法安全/廉价地大量在线交互，只能复用既有控制器留下的日志。
- cite slot：online vs offline RL 的标准区分 1–2 篇（off-policy AC 与 offline/batch RL 各 1）。
- 红线 guard：online **不**写成与 offline 并列的第二贡献（防"两个半 paper 钉在一起"）。

### ¶3 — 高层回答（反直觉优先 + 一句诚实 scope）

- **主旨句（拟）**：「本章的回答有三层，其中两层与直觉相悖。」
- beats（**反直觉优先**，零数字）：
  - 〔反直觉 1·offline 核心〕仅从**简单可部署控制器的日志**中学习，策略即可**追平一个被额外告知真实流场的特权基线**，而部署时完全不需要那条特权信息。
  - 〔反直觉 2·瓶颈〕把性能逼近上界靠的**不是"看得更广"**（更多空间传感器），而是**"如何随时间用好手头这一点信号"**。
  - 〔第三层·边界与算法〕上述结论在一定环境难度内成立；越过阈值后存在一个**所有方法（包括给定特权信息者）都撞上的根本感知极限**；且换用**表达力更强的学习算法并不普遍更优**。
  - 〔诚实 scope 句〕这些结论在一个**受控的流场导航 testbed** 内确立，其精确边界（环境难度 / 传感配置 / 任务设定）在 §5.7 与 §5.9 界定；本章**不**将其包装为对一切流场或平台的通用结论。
- 红线 guard（措辞不得与 §0.4 冲突，但细节不在引言展开）：
  - "更多传感器" 写成 **"非必需、时序访问可替代"**，不写 "无用"。
  - 三种"可有可无"失效方式各异，引言只作整体性陈述，不在此处归并。
  - 不出现"actor 决定全部 mean"一类过头归因；LayerNorm 等"必要基础设施"轴不进引言。

### ¶4 — 贡献定位 + 显式贡献列表

- **主旨句（拟）**：「本章的贡献是关于**"什么决定成败"的实证洞见**，而非一个新的学习算法。」
- beats：
  - 主动声明：所用算法（在线 off-policy actor-critic、行为约束的离线方法、生成式策略先验）**均为已有**；新的是把它们置于**同一受控部署设定**下、用**统一协议 + 多种子统计检验**得到的、可相互印证的发现。
  - **显式贡献 bullet（4 条，负面与正面同列为 finding，§0.5.6）**：
    1. 〔online 诊断〕确立局部信息导航的**可学性**，并将瓶颈定位在**时序信息访问**而非空间传感丰富度。
    2. 〔offline 核心〕证明**仅凭可部署控制器日志即可逼近特权基线**、部署无需特权信息——给出"不依赖任何 simulator-only 信号即可逼近在线教师"的配方。
    3. 〔边界 finding〕刻画该配方的**失效边界**：越过环境难度阈值后出现根本感知极限，连特权示范 / 特权 critic 也无法挽救。
    4. 〔算法 finding〕表明算法优劣是 **regime-dependent** 的：决定性因素是**模仿目标质量与数据特性的匹配**，而非策略先验的表达力。
  - **统一机制 takeaway（引言版一句收束）**：贯穿四条的正向杠杆是"actor 对部署信号的**时序访问**"与"**模仿目标质量与数据 regime 的匹配**"。
- cite slot：所复用算法族的代表原文（offline/batch-constrained、生成式策略先验、asymmetric actor-critic）于此或 §5.2 给出。
- 红线 guard：bullet 措辞守 §0.4；统一 takeaway 不升级为通用 claim。

### ¶5 — 章 roadmap（两幕 × RQ，§0.5.2 句式）

- **主旨句（拟）**：「本章其余部分按**两幕**组织，对应上述问题的两面。」
- beats（role-first，编号见 §E；句式守 §0.5.2）：
  - 预备：§5.2 给出与本章相关工作的**定位**，§5.3 给出三线共享的**统一问题设定**。
  - **Act I（online，回答 RQ1）**：§5.4 确立可学性，并把瓶颈定位在时序信息访问。
  - **Act II（offline，本章重心）**：§5.5 以可部署 baseline 拆出问题设定 → §5.6 主线给出**核心可行性结果**（RQ2）→ §5.7 给出**失效边界**（RQ3）→ §5.8 给出**算法对比**与跨数据源结论（RQ4）。
  - §5.9 统一讨论 + **本章小结**（收束本章统一机制）。
- 红线 guard：roadmap 用机制/结果语态（"§5.6 是…给出…"），不用操作语态（"我们在 §5.6 跑了…"）。
